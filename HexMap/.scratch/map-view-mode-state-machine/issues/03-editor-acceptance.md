# 03 — 编辑器里的端到端验收与结果回写

**What to build:** 在真实编辑器与真实场景里确认重构后的模式切换是对的，并把结果写回规格。

**Blocked by:** 02 — 切换器换成状态机，夹具与接线工具同步换掉

**Status:** ready-for-human

## 为什么单独一张

这一票**只能由人在编辑器里做**：写它的会话里 `pwsh` 不可用（沙箱报 `SetNamedSecurityInfoW failed (Win32 5)`），跑不了 `scripts/run-tests.ps1` 或 TestRunnerApi；而 `sw.unity` 的验收本来就是人工的。单列的好处是：02 的"完成"不依赖于一个 agent 做不到的动作，且这里失败时该退回哪张票是清楚的（几乎总是 02）。

**"编译通过"不等于"行为正确"** —— 这张票存在的全部意义就是把这句话兑现。

## 范围

- [ ] 在编辑器里编译通过、Console 无 error
- [ ] 跑 `HexMap.Sample.Tests.EditMode` 全绿（用仓库既有的测试入口；把实际命令与结果记下来）
- [ ] 打开 `sw.unity` 走人工验收
- [ ] 把结果回写到 `.scratch/map-view-mode-state-machine/spec.md` 第 9 节（哪一次、跑了什么、结果如何）

## 验收

- [ ] EditMode 全绿，且失败的话先退回 02 —— **不要**在这张票里改产品代码去迎合测试
- [ ] 人工：按地图按钮进俯视，UI 换成俯视那一套，**UI 不空白**（空白就说明 UI 相机掉出了会渲染的栈）
- [ ] 人工：再按按钮回 gameplay，UI 换回来，gameplay 相机**原样**回到进去之前的位置与朝向
- [ ] 人工：两个模式下各点一次地图，各自触发**对的**面板/选中（证明点击通道确实跟着模式换了）
- [ ] 人工：**gameplay 模式下滚轮与拖拽再也改不动地图相机**（这是 01 的加固在真实输入下的确认；做法：在 gameplay 里滚滚轮，然后进俯视，看视角是否还是上次退出时的样子）
- [ ] 人工：反复进出两个模式各 5 次，无 Console error、无 UI 空白、无相机漂移
- [ ] 人工：确认 `sw.unity` 文件**没有被改**（孤儿序列化值允许存在；若编辑器保存场景把它们清掉了，记一笔即可，不要手工回填）
- [ ] 结果已回写 spec 第 9 节

## 已知取舍

- 本票不改任何产品代码。如果验收发现的问题需要改代码，那是 02 的活（或新开一张票），**不在这里就地修**——否则"验收"和"实现"混在一起，下次没人知道这份验收到底验的是哪个版本。
- 场景保存时 Unity 清掉孤儿字段是**预期行为**，不是回归。
