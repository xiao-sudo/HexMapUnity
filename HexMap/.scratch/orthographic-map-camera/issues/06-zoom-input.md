# 06 — 缩放输入（捏合 / 滚轮）与文档

**What to build:** 在 `HexMap.Sample` 里加缩放输入适配器（移动端双指捏合、PC 滚轮），**锚点取双指中点 / 鼠标位置**；把 03 的拖拽适配器升级为二维并跟着当前 zoom 换算；更新实现文档。

**Blocked by:** 05 — 相机缩放、焦点与二维平移

**Status:** ready-for-agent

## 范围

### 缩放输入（`HexMap.Sample`）

- [ ] 新增 `OrthographicMapZoomInput`：
  - 移动端：`Input.touchCount == 2` 时用两指距离的**比值**写 `TargetZoom`（旧 Input Manager 没有内置捏合，需手算）
  - PC / 编辑器：`Input.mouseScrollDelta.y` 写 `TargetZoom`
  - 手指全部抬起 / 无滚轮输入时不写任何值
- [ ] **锚点在手势开始时抓一次**（双指中点或鼠标位置），整个手势固定不变；滚轮每次滚动视为一次独立手势
- [ ] 锚点交给相机：调用形如 `TryZoomTo(float targetZoom, Vector2 viewportAnchor)` 的 API，由相机按 6.3 的公式推移中心
- [ ] 手势开始时调 `BeginGesture()`、结束时 `EndGesture()`（让相机在**手势期间**不把镜头拉回焦点，见 05）
- [ ] 锚点归一化坐标约定：`[-1,1]²`，相对视口中心；屏幕水平 → 地图局部 `+X`，屏幕上下 → 地图局部 `+Z`（**别写反**，与 03 同一处易错点）
- [ ] 不做惯性、不做回弹、不做双击缩放

### 拖拽适配器升级（`HexMap.Sample`）

- [ ] `OrthographicMapDragInput` 改为二维：水平写 `Offset.x`，垂直写 `Offset.y`
- [ ] 换算改用**当前 zoom 下的可视宽度 / 可视高度**（`framing.VisibleWidth` / `VisibleHeight`），不要用基础值
- [ ] 方向仍然"内容跟手"；垂直分量的符号要与地图局部 `+Z` 一致（屏幕上方 = 局部 +Z）
- [ ] 拖拽期间不需要声明手势（它不改 zoom），但不得与缩放同时写坏同一次 `Offset`

### 文档

- [ ] `docs/implementation/orthographic-map-camera.md` 新增"缩放与焦点"一节：
  - zoom 定义与数值表（引自 `spec.md` 6.1）
  - `zoom = 1` 是唯一"所有行可见"的端点，以及放大后需要垂直平移的原因
  - 焦点语义："焦点是'想去'的中心，实际中心由夹取产生"；边缘 Hex 放大后仍不在正中心
  - **锚点必须在手势开始时抓一次**、每帧增量式套公式、边缘不加补偿这三条
  - **焦点只在 `FocusOn` 与"非手势的 zoom 变化"生效**；拖拽不会把镜头拉回焦点
  - 失败模式表补上"捏合时地图从手指下滑走 / 抖动 / 拖不动"三行（`spec.md` 第 4 节已写好）
- [ ] 若新增了输入组件，接线一节补上它的槽位

## 验收

- [ ] **用一个临时 stub harness 验算锚点公式与拖拽换算**并全部通过：`anchor = (0,0)` 退化为中心锚点；`anchor ≠ 0` 时锚点下的世界点在缩放前后**位置不变**（比例断言）；边缘情形夹取后不越界；拖拽换算用当前 zoom 的可视尺寸；退化输入（屏幕宽/高为 0、zoom 相同、两指距离为 0）被忽略
- [ ] 在 `map.unity` 里手动验：双指捏合以中点为中心缩放、地图不从手指下滑走、无抖动、到端点硬停
- [ ] PC 滚轮以鼠标位置为中心缩放
- [ ] 放大后上下左右都能拖；拖到别处后再捏合，**镜头不会跳回焦点**
- [ ] 缩回最远（zoom = 1）⇒ 镜头回正中、所有行可见
- [ ] C# 编译通过

## 已知取舍

- `HexMap.Sample` 只被 PlayMode 测试程序集引用，EditMode 测不到，所以输入适配器**没有自动化测试**（与 `spec.md` 2.7 一致）；验算靠临时 harness + 手动。
- 不做双指平移（两指同时平移时只处理缩放，中点漂移被"锚点抓一次"吸收）。
- 不在本票改 `map.unity` 的接线之外的东西。
