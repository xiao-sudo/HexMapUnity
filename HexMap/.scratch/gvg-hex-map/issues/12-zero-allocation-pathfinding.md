# 12 — 低分配寻路工作区与可复用路径结果

**What to build:** 在不改变通用 Hex 寻路结果语义的前提下，为重复运行时寻路提供由调用者创建并复用的工作区、请求、路径结果和世界坐标输出缓冲区，使预热后的寻路热路径不产生托管内存分配。

**Depends on:** 04 — 通用寻路与路径表现数据。

**Status:** ready-for-agent

## 问题陈述

当前通用 Hex 寻路在每次搜索中创建目标集合、父节点字典、距离字典、队列、路径列表、只读包装器和 PathResult 对象。请求构造还会复制目标列表，世界坐标转换会创建新的 Vector3 列表。

对于战场中重复执行的单位移动、目标刷新和路径重算，这些短生命周期对象会制造持续的托管内存分配和垃圾回收压力。仅把局部变量移动为成员变量还不够，因为请求、结果和世界坐标转换仍然会在 API 边界分配，也无法明确工作区的所有权、并发限制和结果生命周期。

## 解决方案

提供一个由调用者控制生命周期的寻路 API。调用者在热路径之外创建并持有地图绑定的 HexPathfinder、PathSearchWorkspace、可复用请求、PathResult、路径 List<HexCell> 和世界坐标 List<Vector3>。

寻路器只负责使用工作区、读取稳定的请求和策略对象、填充调用者提供的结果，不在重复搜索期间创建集合、数组、结果对象或只读包装器。搜索容器继续使用可复用的 Dictionary、HashSet 和 Queue，并在每次搜索开始时清空、保留已有容量。

路径结果使用调用者提供的 List<HexCell>。世界坐标转换使用调用者提供的 List<Vector3>。缓冲区不足时返回明确的输入失败原因，不允许 List 在热路径中自动扩容。

此改造不改变现有通用寻路的目标过滤、通行规则、最近目标选择、确定性 tie-break、路径顺序、失败原因或路径成本语义。

## 用户故事

1. 作为玩法开发者，我希望为一张 Hex 地图创建可复用的寻路器，从而重复寻路时不必每次创建新的寻路引擎。
2. 作为玩法开发者，我希望在热路径之外创建寻路工作区，从而临时搜索状态只在初始化阶段分配。
3. 作为玩法开发者，我希望工作区绑定一张 Hex 地图，从而复用容器拥有稳定容量，且不会误用其他地图的状态。
4. 作为玩法开发者，我希望使用可复用的寻路请求，从而在多次搜索之间更新起点或目标时不必重新创建请求对象。
5. 作为玩法开发者，我希望复用型请求内部拥有并复用目标 List，从而动态目标选择不会因为外围每次创建数组或 List 而分配。
6. 作为玩法开发者，我希望仍然保留具有防御性目标复制语义的安全型请求，从而在非热路径场景下可以优先选择输入安全性。
7. 作为玩法开发者，我希望提供可复用的路径规则对象，从而 CanPass 和 CanEnter 不需要依赖每次寻路创建的闭包或上下文对象。
8. 作为玩法开发者，我希望一次寻路期间路径规则观察到稳定的地图和玩法状态，从而结果保持确定且可复现。
9. 作为玩法开发者，我希望复用父节点、距离、目标、已评估目标和待处理节点容器，从而 BFS 搜索不会每次创建集合。
10. 作为玩法开发者，我希望清空可复用容器时保留其容量，从而首次搜索付出初始化成本后，后续搜索不会重新申请内部存储。
11. 作为玩法开发者，我希望寻路直接写入调用者提供的 List<HexCell>，从而路径重建不创建中间坐标列表或格子列表。
12. 作为玩法开发者，我希望路径回溯后原地反转路径列表，从而无需额外缓冲区也能得到从起点到目标的有序路径。
13. 作为玩法开发者，我希望复用同一个 PathResult，从而成功和失败搜索都不会创建新的结果对象或只读包装器。
14. 作为玩法开发者，我希望复用型结果明确表示会被下一次搜索覆盖，从而调用方不会把临时结果误当成持久快照。
15. 作为玩法开发者，我希望失败搜索清空任何部分路径，从而业务层不会误执行不完整路线。
16. 作为玩法开发者，我希望输出缓冲区过小时得到明确的容量失败，从而运行时不会为了 List 自动增长而偷偷分配。
17. 作为玩法开发者，我希望使用调用者提供的 List<Vector3> 转换世界中心点，从而移动表现也能避免重复分配。
18. 作为玩法开发者，我希望世界坐标仍然是派生表现数据，从而权威结果只保存 Hex 路径，不绑定某个布局的坐标缓存。
19. 作为玩法开发者，我希望热路径使用索引访问列表，从而接口枚举器的运行时差异不会引入额外分配。
20. 作为玩法开发者，我希望寻路器能明确约束重入使用，从而一个可复用工作区不会被嵌套搜索破坏。
21. 作为玩法开发者，我希望 API 明确一个工作区不是线程安全的，从而并行调用者会创建独立工作区而不是共享可变搜索状态。
22. 作为玩法开发者，我希望最近目标选择和确定性 tie-break 行为保持不变，从而性能重构不会改变玩法决策。
23. 作为玩法开发者，我希望预热后的重复寻路分配为零字节，从而频繁重算路线不会制造可避免的垃圾回收峰值。
24. 作为维护者，我希望分配测试在最高可用运行时 seam 上测量，从而测试验证真实的复用型 API，而不是只验证私有容器细节。
25. 作为维护者，我希望语义测试继续覆盖成功和失败行为，从而性能重构不会悄悄改变通用 Hex 地图契约。

## 实现决策

- 将当前静态、每次调用创建临时状态的寻路器改为实例 HexPathfinder，实例绑定一张 HexMap 和一个调用者创建的 PathSearchWorkspace。
- 不保留旧的自动分配寻路入口作为主要 API。复用型 API 要求调用者显式提供工作区和结果对象。
- 保持通用 HexMap 边界独立于 GVG 概念。寻路器只处理 Hex Cell、坐标、目标和调用者提供的规则，不理解地块、公会归属、战斗状态或城池类型。
- 工作区在寻路热路径之外创建。其 Dictionary、HashSet 和 Queue 容器按固定地图容量准备，并在每次搜索开始时清空而不释放内部存储。
- 本次改造继续使用按坐标索引的可复用容器。是否改为按 Cell ID 索引的数组，留给后续有明确 profiling 证据时单独处理。
- 增加复用型请求表示，由 request 一次性创建或接收目标 List。调用者通过 ClearTargets 和 TryAddTarget 在两次搜索之间更新目标；一次搜索期间必须保持 request、目标内容和策略稳定，TryAddTarget 不得触发自动扩容。
- 保留具有防御性复制语义的安全型请求，供非热路径调用者使用。
- 复用型寻路规则使用调用者拥有的 IHexPathPolicy，公开 CanPass(HexCell) 和 CanEnter(HexCell)。策略对象跨搜索复用，并且一次搜索期间保持稳定。
- 保留现有规则边界：起点不要求通过 CanPass；中间格必须通过 CanPass；目标格只通过 CanEnter 判断；被拒绝的目标不能成为中间格。
- 结果对象由调用者创建并复用，持有调用者提供的路径 List<HexCell>，暴露当前状态、原因、成本、抵达目标和只读路径视图，不在每次搜索创建只读包装器。
- 每次搜索开始时清空结果路径。父节点回溯时将路径反向写入结果列表，完成后原地反转，再向调用者暴露。
- 复用型结果只在下一次覆盖它的搜索前有效。调用者需要持久路线时，必须显式复制路径到自己的存储。
- 路径重建不得触发 List 扩容。调用者通常应按地图格子数量准备容量；若路径 List 容量不足，返回 InvalidInput 与 ResultCapacityExceeded，清空部分路径，并将成本和抵达目标恢复为失败值。
- 容量不足时不得调用 EnsureCapacity，也不得在搜索期间通过其他方式分配新存储。
- 世界中心点转换改为填充调用者提供的 List<Vector3>。方法清空并填充列表，写入前检查容量，容量不足时返回失败，不自动扩容。
- PathResult 只对 Hex 路径拥有权威性。世界中心点仍然是派生表现数据，不缓存到结果对象中。
- 请求目标和结果格子在热路径中使用索引访问，不使用接口类型的 foreach 枚举。
- 一个工作区在一次搜索活动期间只能被一个调用使用。不支持同一工作区的并发或并行使用，策略回调也不能重入同一个寻路器。
- 保留所有确定性行为：重复目标去重、无效目标过滤、起点即目标成功、最近可达目标选择、按坐标顺序裁决等代价目标、固定邻居顺序裁决等长路径、从起点到目标的路径顺序，以及成本等于路径边数。
- HexMap 运行时新增的私有和实例字段遵守 m_ 前缀约定。

## 测试决策

- 测试优先验证外部可观察的路径行为和生命周期契约，不绑定私有字段布局或具体容器实现。
- 调整现有 HexPathfinding EditMode 测试，使其通过复用型 HexPathfinder、request、workspace 和 result API 运行，同时保留当前行为覆盖。
- 继续覆盖有效路径、起点即目标、起点移动规则、最终目标进入规则、被拒绝目标、无效起点、无效目标、空目标、不可达目标、多目标、重复目标、确定性目标 tie-break、确定性邻居顺序 tie-break，以及规则对象状态传递。
- 增加复用型 request 在两次搜索之间更新起点和目标的测试，确认新数据生效，并确认寻路期间目标所有权契约不被破坏。
- 增加同一个 result 连续经历成功、失败、再次成功的测试，确认路径、状态、成本、抵达目标和失败原因都能正确重置，失败时不会留下部分路径。
- 增加容量不足测试，确认输出 List 不会被自动扩容，结果返回 ResultCapacityExceeded，路径为空，失败字段保持约定值。
- 增加世界坐标 List 复用测试，确认每次转换都会清空并依据权威 Hex 路径重新填充。
- 增加足够容量下重复填充路径和世界坐标的测试，确认路径顺序、成本、抵达目标和世界中心点正确。
- 在最高可用运行时 seam 上增加重复寻路分配测试：先创建地图、寻路器、工作区、复用型 request、策略、result 和输出列表，完成预热后再测量重复搜索。
- 分配测试不把首次 JIT、泛型初始化、测试框架初始化和对象构造计入测量区间。
- 测量区间内使用预先创建的策略回调，不创建 lambda、数组、request、result 或断言辅助对象。
- 分配测试至少覆盖普通成功路径、接近整张地图的搜索、起点即目标、无可达目标，以及重复世界中心转换。
- 测试沿用现有纯 C# Unity EditMode 路径测试作为先例，使用小型合成 Hex 地图，不依赖场景、GameObject 或渲染对象。

## 非目标

- 不把 BFS 改为 A*、Dijkstra 或其他搜索算法。
- 不在本 issue 中把坐标字典和集合全部改成按 Cell ID 索引的数组。
- 不支持共享一个工作区的并发、并行、多线程或 Unity Job 寻路。
- 不把一个 PathResult 变成跨搜索仍保持独立数据的不可变持久快照。
- 不增加全局静态工作区，也不引入隐式全局对象池。
- 不负责阻止调用者在需要长期保存时显式复制临时结果。
- 不优化调用者自定义策略内部的分配；本 issue 只规定策略回调在热路径中不得主动分配。
- 不在 PathResult 中缓存或复用世界坐标结果。
- 不处理路径平滑、路线表现、移动播放或 GVG 路线失效。
- 不改变地块归属、阻挡、开放状态、公会规则或其他 GVG 玩法逻辑。
- 不修改场景、GameObject、渲染或 Unity 表现层。

## 进一步说明

- 本 issue 细化 issue 04 中通用寻路能力的生命周期和分配契约，不替换 issue 04 已确定的领域边界和确定性结果要求。
- List<T> 被选作可复用路径缓冲区，是因为调用者可以跨搜索保留它；但 List 的自动增长必须视为容量准备错误，不能作为热路径的正常行为。
- 文档和测试需要区分初始化分配与稳定运行分配。稳定运行零分配不意味着地图、工作区、策略、请求或结果构造阶段零分配。
- 需要同时执行多个独立搜索时，每个活动搜索必须拥有独立的寻路器、工作区和结果集合。
- 第一版实现应优先保持一个最小公共 seam：复用型 HexPathfinder 填充复用型 PathResult；世界中心点转换作为独立的调用者提供输出操作。
