# Domain Docs

How the engineering skills should consume this repository's domain documentation.

## Before exploring

- Read `CONTEXT.md` at the repository root when it exists.
- Read relevant ADRs under `docs/adr/`.
- Proceed silently when these files do not yet exist; create them only when domain decisions require it.

## Vocabulary and decisions

- Use the project's glossary vocabulary in issue titles and technical documentation.
- Surface conflicts with existing ADRs instead of silently overriding them.

## Layout

This is a single-context repository. Domain context belongs in root `CONTEXT.md`; architectural decisions belong in `docs/adr/`.
